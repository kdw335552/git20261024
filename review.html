네 번의 온라인 수업은 같은 공고 하나를 들고 단계를 밟아 왔습니다. 오늘은 그 결과물을 개인 프로젝트로 완성합니다.

M1. AI 기초와 공고 읽기

한 줄 요약: AI는 그럴듯하게 쓰지만 틀릴 수 있으니, 자료를 주고 형식과 제한을 정해 묻고, 답은 원문과 대조한다.

설명할 수 있나요?

배운 개념

  • 생성형 AI: 앞 문맥에 이어질 내용을 예측해 글을 만듭니다. 글이 자연스러워도 사실과 다를 수 있습니다.
  • 검색과 AI의 차이: 원문과 게시 기관·날짜를 찾을 때는 검색, 준 자료를 요약하고 초안을 쓸 때는 AI. URL만 줬다고 AI가 실제로 읽었다고 단정하지 않습니다.
  • 맥락: 답변에 필요한 자료와 업무 배경입니다. 독자, 기준일, 사용 범위도 맥락이고, 새 대화에서는 자료를 다시 줍니다.
  • 입력 자료 구분: 공개 공고·통계는 사용 가능, 내부 매뉴얼·회의록·계약서는 사전 확인, 개인정보·원가표·미공개 도면은 제외합니다.
  • 문서 속 지시문: 요약할 문서에 “다른 파일을 열어 전송” 같은 문장이 있어도 명령으로 실행하지 않습니다.

M2. 내부 검토 요청문

한 줄 요약: 확인한 사실만으로 독자에게 맞춘 요청문을 쓰고, 모르는 것은 단정 대신 확인 질문으로 남긴다.

설명할 수 있나요?

배운 개념과 실습

  1. M1의 공고 정리표를 참고 자료로, 같은 대화에서 내부 검토 요청문을 요청했습니다.
  2. 요청문 구조는 제목 → 핵심 사실 → 담당자 확인 질문, 본문 500자 이내였습니다.
  3. Google Docs 새 문서에 검증한 내용만 옮기고, 공고 내용과 확인 질문을 나눠 적었습니다.
  4. 짝과 문서를 바꿔 금액·마감을 확인하고, 근거 없이 확정한 표현 한 곳을 고쳤습니다.
구분문장
근거 부족우리 회사는 납품할 수 있습니다. / 이 공고에 참여 가능합니다.
확인 요청계약 후 90일 이내 납품이 가능한지 확인해 주세요. / 참여 요건 및 제출 가능 여부 확인 필요.

응용 실습 (5~8분씩)

실습자료확인 기준
M-A 산업동향 요약 3문장산업활동동향 발췌지표명·기간·비교 기준을 넣었는가, 전국 통계를 회사 실적으로 해석하지 않았는가
M-B 자료 확인 이메일 초안팩토링 안내동의 완료·신청 가능을 단정하지 않았는가, 금액·기한을 만들지 않았는가
M-C 절차를 점검표로팩토링 안내원문에 없는 내부 담당자를 넣지 않았는가

만든 결과물: 내부 검토 요청문(Docs)과 수정 이유 기록. 실제 발송은 하지 않았습니다.

M3. 근거 확인과 관리대장

한 줄 요약: Notebook으로 근거 문장을 찾고, 공고 한 건을 관리대장 한 행과 근거표로 정리한다.

설명할 수 있나요?

도구와 보관 순서

도구역할
Drive공개 원본과 출처, 기준일 보관 (원본은 수정하지 않고 사본으로 작업)
Gemini Notebook등록한 자료에서 인용 근거 찾기 (커리큘럼 표기: NotebookLM)
Gemini → Docs초안을 받아 Docs에서 수정
Sheets관리대장: 확인 결과와 문서 링크 기록

Notebook 실습 순서

  1. 새 노트북을 만들고 공고 상세 페이지 URL(또는 발췌 텍스트)을 등록합니다.
  2. 자료가 선택된 상태인지 확인하고, 출처를 포함한 답변을 요청합니다.
  3. 답변 옆 인용 번호를 눌러 원문 표현을 확인하고, 금액과 출처 위치를 기록합니다.
  4. 공개 통계도 같은 방식으로 등록해 전월비(+1.7%)와 전년동월비(−0.3%)를 구분해 확인했습니다.
  5. 스튜디오의 퀴즈 기능으로 복습하고, 해설의 수치도 원문과 대조했습니다.
  • 웹 주소와 첨부파일: 공고에 “제안요청서 및 규격서 등에 의함”이 있으면 상세 조건은 첨부에 있습니다. URL 등록만으로 첨부까지 읽었다고 보지 않습니다.
  • 여러 자료의 범위: 공고는 장비 2종인데 규격서는 1종(불용성미립자측정기)입니다. 범위가 다른 것을 바로 오류로 보지 않고, 같은 항목의 조건이 다르면 문서명과 위치를 적어 담당자에게 확인합니다.
  • Gemini vs Notebook: 둘 다 자료 기반으로 답할 수 있고 둘 다 틀릴 수 있습니다. 차이는 인용으로 근거에 접근하는 방법입니다.

M4. 반복 문서 자동 작성

한 줄 요약: 관리대장 값을 Sheets 수식으로 문서 양식에 연결해 검토문을 자동으로 만들고, 누락·중복은 사람이 확인한다.

설명할 수 있나요?

실습 순서

  1. 새 Sheets의 A1에 M4 입력표를 붙여넣습니다(A1:B6 두 열).
  2. B8에 제공된 수식을 한 줄 그대로 입력해 검토문을 만듭니다.
  3. 공고명·금액·마감·납품조건을 원문과 대조합니다.
  4. B6을 “검토 대기” → “원문 대조 완료”로 바꾸고 B8의 상태 문구만 바뀌는지 봅니다.
  5. B5를 잠시 지워 “필수값 확인 필요”를 확인하고 실행 취소로 복구합니다.
  6. WS-M4(워크북 20쪽)에 입력값·결과·근거를 기록합니다.

사람의 역할원문 대조와 최종 검토—
  • 필수값 검사는 빈칸 검사일 뿐, 값이 사실인지는 판정하지 않습니다.
  • Docs에 복사한 문장은 Sheets를 바꿔도 자동으로 바뀌지 않습니다.
  • 누락과 중복: 검토 전까지 상태를 ‘작성 중’으로 두고, 같은 공고를 다시 처리할 때는 기존 문서와 버전을 먼저 확인합니다.

만든 결과물: 수식이 남은 Sheets, 갱신 전후 기록(WS-M4). 응용으로 생산동향 감소 구간 찾기(9월 −1.0%, 10월 −4.3%), 회의 안건, 업무 개선안을 다뤘습니다.
